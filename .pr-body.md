## Port the Zhouyi AIPU driver to build on mainline/generic kernels 7.x

The driver currently targets the CIX vendor kernel (`CONFIG_ARCH_CIX`, 6.6-era APIs). This branch ports it to build against **Ubuntu generic kernels 7.x** (e.g. `7.0.0-29-generic`, aarch64) so the AIPU can be used without switching kernels — no downgrade needed.

The port was verified by compiling the full module against a 7.1.5 kernel tree. Only arm64 cache-maintenance inline asm (`dc`/`dsb`) fails to link on the x86_64 host used for verification; it assembles fine on aarch64.

### API migrations

**`sky1/sky1.c`** — SCMI perf-domain helpers were removed in 7.x:
- `scmi_device_set_freq()` → `dev_pm_opp_set_rate()`
- `scmi_device_get_freq()` → `dev_pm_opp_find_freq_ceil()`
- `scmi_device_opp_table_parse()` dropped (the OPP table is auto-populated by the perf domain's `attach_dev` callback)
- ACPI perf-domain attach via `fwnode_property_match_string()` + `genpd_dev_pm_attach_by_id()` (replaces the removed `fwnode_dev_pm_domain_attach_by_name()`)
- includes: `<linux/scmi_protocol.h>` → `<linux/pm_opp.h>` + `<linux/property.h>`

Also in `sky1.c`:
- `pm_runtime_put()` returns `void` since 6.13 — drop return-value handling
- `platform_driver::remove` returns `void` since 6.11 — version-guarded signature (`KERNEL_VERSION(6,11,0)`), keeps the 6.6-era `int` form for older kernels

**`aipu_mm.c`**:
- `MAX_ORDER` → `MAX_PAGE_ORDER` (renamed in ≥6.8) — `AIPU_MAX_ORDER` compat macro
- `pgprot_dmacoherent()` moved out of the default include chain — `#ifndef` fallback to `pgprot_noncached()`

**`aipu_dma_buf.c`**:
- `MODULE_IMPORT_NS(DMA_BUF)` → `MODULE_IMPORT_NS("DMA_BUF")` (the macro no longer stringifies its argument; the quoted form works on both old and new kernels)

### Build-infra fixes
- `driver/Makefile`: `EXTRA_CFLAGS` was removed from kbuild → `ccflags-y`; `-I$(PWD)/` → `-I$(M)/` (under `make -C` the outer `PWD` resolves to the kernel dir, so the include flags were silently dropped and headers never reached the compiler — this also fixes the "headers not found" build failure on the vendor kernel)
- `driver/dkms.conf`: dropped the `CONFIG_ARCH_CIX` `BUILD_EXCLUSIVE_KERNEL` gate so DKMS builds on generic kernels

### Files
- `PORT-NOTES.md` — port rationale and build instructions
- `board-install.sh` — DKMS build/install/load helper for the board

### Testing status
- Full module compiles against kernel 7.1.5 headers (x86_64 host; link stops only at arm64-only inline asm)
